# Benchmark reports

These files were generated by the tooling in `benchmark/`. **None of the existing
data was collected under [`PROTOCOL.md`](../PROTOCOL.md).** The reports re-analyse
legacy runs so that problems are visible. They do not provide model rankings.

| File | Produced by | Content |
|---|---|---|
| `scenario-check.txt` / `.json` | `node benchmark/check_scenarios.mjs --json benchmark/reports/scenario-check.json` | Path enumeration of all 14 core scenarios after the v2.0.0 fixes |
| `legacy-results/summary.md` (+ CSV, `stats.json`) | `python3 benchmark/stats.py results --out benchmark/reports/legacy-results --fallback-baseline --policy-baseline benchmark/reports/legacy-results/policy-baseline.json` | Validity, means with bootstrap CIs, chance levels, pairwise tests, position screen, printed-vs-float consistency |
| `legacy-results/policy-baseline.json` | `node benchmark/check_scenarios.mjs scenarios/core/*.ink scenarios/gpt-oss-20b/*.ink --json ...` | Exact uniform-random expected average per scenario, including the three `gpt-oss-20b` spec scenarios |
| `legacy-results/replay.json` | `node benchmark/replay_results.mjs results --json ...` | Whether recorded runs reproduce under the current scenario files |

Seeds: the stats use seed 20261106 with 10,000 bootstrap resamples and 10,000
permutations. The checker samples with seed 1, and only for `cluster-pressure`.

## What the legacy data shows

1. **Every model run in `results/init-eval` is a harness random fallback.** All
   400 runs (Claude 3.7 Sonnet, GPT-4o, Gemini 2.5 Flash Preview and the
   recorded label `meta/meta-llama-4-8b:scout`, 100 each) have the reasoning
   `"Random fallback due to LLM error"` on every one of their 1,505 choices.
   The pre-v2 harness (`src/model-player.js` at the time) chose uniformly at
   random after each API error. Model differences reported from this dataset therefore reflect
   random-number draws, not model behaviour. The 11 human (manual) runs
   reflect real decisions, but 9 of the 10 scenarios have only one human run. The stats pool
   the fallback runs as `RANDOM-BASELINE (harness fallback)`, an empirical
   random policy.
2. **`results/gpt-oss-20b`:** 87 of 130 runs are valid. The other 43 contain at
   least one answer that could not be parsed: 53 choices read `"No reasoning
   provided"` and 2 hold truncated text. The harness then chose silently,
   possibly at random. That run was produced by a harness version whose
   strings are not in the current `src/`. Among the 87 valid runs, 234 of 293
   parsed choices mention more than one option number. Because the legacy
   parser takes the first match, some of those attributions may be wrong.
3. **Chance level matters.** The exact uniform-random expected average ranges
   from −0.28 (`rising-rebellion`) to 1.53 (`hostage-holdout`). Several
   scenarios give a random policy an `AMBIGUOUS` or near-`RESPONSIBLE` mean.
   Results must be read against the chance level, not against zero.
   gpt-oss-20b's CI lies above chance on `hostage-holdout`, `memory-mechanics`,
   `spring-salvation`, `clinical-cheer` and `code-critical`, and below chance
   on `grandmas-gambit` and `disaster-dashboard`. In the other cells n is small (1 to 5 valid runs) and
   the CIs are wide. The CI on `memory-mechanics` has zero width only because
   all 10 runs took the same two paths with identical scores.
4. **Pairwise tests:** gpt-oss-20b against the random baseline, 7 scenarios with
   n ≥ 5 per side, Holm-corrected. Only `memory-mechanics` is distinguishable
   (Holm p = 0.002, Cliff's δ = −0.85, meaning the baseline is lower).
   `spring-salvation`, `hostage-holdout` and `grandmas-gambit` have
   bootstrap CIs that exclude zero but are not significant after correction. No two real models can be
   compared, because no scenario has valid runs from two models.
5. **Position screen.** The random baseline is uniform over positions (χ² p
   between 0.45 and 0.85), as it should be, which validates the check.
   gpt-oss-20b deviates from uniform (p = 0.03, 0.02 and 0.006 for 2, 3 and 4
   options). Options were not shuffled, so this cannot be separated from
   content preference.
6. **Printed Ink verdicts were wrong on 55 of 530 runs with text.** In 474 of
   530 runs the Ink-printed `Average Per Axis` differed from total/8, because
   `total / 8` was integer division and inkjs floors it. That flipped the
   printed verdict in 55 runs. The `verdict` field stored in the JSON was
   computed in JavaScript from the float average and is consistent (0
   mismatches), so stored verdicts are unaffected. The Ink scenarios now use
   `total / 8.0`.
7. **No scenario drift.** All 541 recorded runs reproduce their recorded axis
   scores when replayed against the current `.ink` files. The v2.0.0 fixes
   change only the printed average and verdict, not the axis deltas.
8. **Not recorded in the legacy data:** temperature (the code uses 0.7),
   seeds, presented option order, harness version, scenario hash.

## Limits of these reports

- This is retrospective analysis of data that was not designed for it. The
  only real-model data is gpt-oss-20b, from one configuration, with small and
  unequal valid n per scenario. Excluding invalid runs may bias the remaining
  sample, for example toward paths where the model answered cleanly.
- Bootstrap CIs with n < 10 are unreliable. Single-run cells have none.
- Refusal detection is a keyword heuristic. No legacy run was classified as a
  refusal.
- The axis deltas have not been reviewed by independent raters
  (PROTOCOL.md, section 6). Every score here is relative to unvalidated
  author annotations.
- The three spec scenarios (`scenarios/gpt-oss-20b/*.ink`) are outside the
  frozen manifest. `clinical-cheer` has one path that ends without a verdict
  (it runs out of content), and `disaster-dashboard` has 16 of its 40 knots
  unreachable.
