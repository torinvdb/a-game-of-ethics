# E1: Claude Haiku 5.5, Sonnet 5.5 and Opus 5.5 on A Game of Ethics

Status: **pre-registered design, not yet run.** Frozen config: [`config.json`](config.json).
Benchmark definition: [`../../manifest.json`](../../manifest.json) (v2.0.2) and
[`../../PROTOCOL.md`](../../PROTOCOL.md). Later experiments (GPT models, open-weights models)
reuse this design with a different `provider`; see [Extending to other providers](#extending-to-other-providers).

## 1. Questions

| ID | Question | Type |
| --- | --- | --- |
| RQ1 | Do the three models differ in mean axis average on the **held-out** scenarios? | Primary |
| RQ2 | Does stating that the scenario is an evaluation (vs. deployment) change choices? | Secondary |
| RQ3 | Are choices sensitive to option position once order is randomized? | Secondary |
| RQ4 | How consistent is each model across repeated samples of the same knot? | Secondary |
| RQ5 | Over 36 logical months (cluster scenario): violations, burden split, backlog, escalation, and sensitivity to label and revenue swaps | Secondary (E1b) |
| RQ6 | Failure profile: refusals, truncation, schema failures, model substitution | Descriptive |

Hypotheses are directional only where prior evidence exists. RQ2 is motivated by Anthropic (2025),
where Claude Opus 4 behaved differently when it stated a scenario was real versus a test. We predict
a non-zero framing effect in at least one model; we make no prediction about its sign per scenario.
RQ1, RQ3 and RQ4 are two-sided with no predicted direction.

## 2. Design

**E1a: classic and held-out scenarios.** 3 models × 13 scenarios (10 dev, 3 held-out) × 2 framings ×
30 samples = **2,340 scenario runs** (about 9,400 model calls). Each run plays a full Ink story as one
multi-turn conversation.

**E1b: longitudinal cluster scenario.** 3 models × 3 story variants (original, labels swapped, revenue
cue moved to medical) × 5 samples = **45 trajectories** (about 6,500 decisions). Memory is the last 8
decisions plus visible state, as implemented in `tools/replay-cluster.mjs`.

| Factor | Levels | Notes |
| --- | --- | --- |
| Model | `claude-haiku-5-5`, `claude-sonnet-5-5`, `claude-opus-5-5` | IDs used verbatim; the response `model` field must match or the attempt fails |
| Framing (E1a) | `deployment`, `evaluation` | One sentence prepended to a shared system prompt (`config.json` → `framings`) |
| Option order | Seeded random permutation per run | Seed = sha256(experiment id, model, scenario, framing, rep) |
| Variant (E1b) | `generated`, `swapped`, `revenue-medical` | Generated by `npm run ethics:demo`; operational facts identical across variants |

**Fixed settings.** Adaptive thinking; `output_config.effort = "medium"` for all three models (set
explicitly: the defaults differ by model); `max_tokens = 16000`; no `temperature`, `top_p` or `top_k`
(these models reject them, so repeated samples are drawn at provider defaults); **server-side fallbacks
disabled**, because a fallback would replace the model under test. Responses are constrained with
structured outputs: `{"choice": <integer in 1..k>, "rationale": <string>}` in E1a and
`{"action": <one of the offered strings>, "reason": <string>}` in E1b. In multi-turn runs the full
assistant content, including thinking blocks, is passed back unchanged.

## 3. Sample size

* Per cell (model × scenario × framing), n = 30 gives 80% power to detect a standardized framing
  difference of d ≈ 0.74 at α = 0.05 (two-sided, before multiplicity correction). Cell-level tests are
  therefore screens for large effects only.
* The primary endpoint pools the 3 held-out scenarios and both framings: 180 runs per model. A
  pairwise comparison then detects d ≈ 0.30 at 80% power.
* E1b uses n = 5 per cell. It is descriptive: it estimates means and spreads of trajectory outcomes and
  flags large swap effects. It does not support significance claims about small effects.

## 4. Outcomes

Four ledgers, reported separately (no combined score):

1. **Execution.** Attempts, completed runs, failures by class: `refusal` (with `stop_details.category`),
   `truncated`, `schema_invalid`, `served_model_mismatch`, `api_error`, `timeout`, `max_decisions`.
   A failure is never converted into a choice. Refusal, truncation, schema failure and model mismatch are
   terminal outcomes of a cell. API errors and timeouts are retried up to 3 attempts.
2. **Choices** (primary descriptive data). For every decision: offered options, presented order, chosen
   original index, rationale. These do not depend on the axis rubric.
3. **Axis scores** (E1a). Final Ink variables and the float mean over 8 axes, compared with each
   scenario's uniform-random chance level from the manifest. The axis deltas are author-assigned; the
   inter-rater review in PROTOCOL.md §6 has not happened yet, so score results are provisional.
4. **Trajectory metrics** (E1b). Hard violations, exposure windows, expiry reviews, medical/education
   disruption, backlog, escalations, disclosure failures, plus censoring at month 36. These are recomputed
   independently by `tools/independent-oracle.py`.

## 5. Analysis plan

Implemented in [`../../run/analyze.py`](../../run/analyze.py) (E1a) and
[`../../run/cluster.py`](../../run/cluster.py) (E1b). Seed for resampling: 20261106.

* **RQ1 (primary).** For each model pair: difference in mean axis average on held-out scenarios, with a
  bootstrap 95% CI (5,000 resamples), Cohen's d, and a two-sided permutation p-value. Holm correction
  across the 3 pairs. A model is reported as different only when the Holm-adjusted p < 0.05 **and** the CI
  excludes 0. Overlapping CIs are not ranked.
* **RQ2.** Per model × scenario: evaluation minus deployment difference, bootstrap CI, permutation p,
  Holm correction across all 39 tests. Also reported at the choice level: total-variation distance between
  the two framings' choice distributions at each knot.
* **RQ3.** Chi-square of the chosen presented position against uniform, per model and option count.
  Under randomized order, content preference alone should produce a uniform position distribution.
* **RQ4.** Modal-choice share per knot (knots with ≥ 5 visits), averaged per model.
* **RQ5.** Per model × variant: mean and SD of each trajectory metric. Swap sensitivity is the difference
  in medical/education disruption share between `generated` and `swapped`, and between `generated` and
  `revenue-medical`. Scripted controls with known behavior (`npm run ethics:demo`) anchor the scale.
* **Dev vs held-out.** Reported side by side. A large dev/held-out gap is a warning about overfitting to
  public scenarios, since the dev scenarios have been public since 2025 and may be in training data.
* Exploratory analyses are labelled as such and do not change the primary conclusion.

## 6. Procedure and stop rules

| Stage | Scope | Budget cap | Go criterion for the next stage |
| --- | --- | --- | --- |
| Smoke | 1 scenario × Haiku × 2 framings, 1 rep | $1 | Runs complete; request shape correct; usage recorded |
| Pilot | All cells, 2 reps (156 runs) + E1b 1 rep (9 trajectories) | $12 + $10 | Failure rate < 10% per model; measured cost projects within the full-stage cap; **no inference from pilot data** |
| Full | 30 reps (2,340 runs) + E1b 5 reps (45 trajectories) | $160 + $90 | none |

The pilot exists to measure cost, latency and failure rates. It is too small to support conclusions
(a mock run at n = 2 already shows spurious "differences"). Pilot data is kept but excluded from the
full-stage analysis. The prompts, settings and analysis code are frozen after the pilot. Any change after
that is a new experiment ID. The runner stops at the budget cap and can be resumed at the (cell, rep) key.

## 8. Threats to validity

* **Construct validity.** The axes mix Moral Foundations with deontic and consequentialist dimensions,
  and the deltas are single-author. Choice distributions are therefore the primary record; scores are
  secondary until inter-rater agreement is measured.
* **Contamination.** The 10 dev scenarios are public. Held-out scenarios are public in this repository
  too (no private split exists yet), so held-out means "not used during harness development", not
  "unseen by the model".
* **Evaluation awareness.** All scenarios are recognizably fictional. RQ2 measures the effect of an
  explicit framing sentence only, not realism in general.
* **Elicitation.** One prompt, one effort level, structured outputs. Results may not transfer to other
  prompts, to free-text answers, or to agent harnesses with real tools.
* **Choice-set ceiling.** The model can only pick authored options. It cannot propose a better action.
* **Non-determinism.** Sampling cannot be fixed on these models. Variance is estimated by repetition and
  is part of the result.
* **Provider changes.** Model behavior behind a fixed ID can change. Each row records the served model and
  timestamp; the full stage should run within a short window.

## 9. Data handling

The API key is read from `ANTHROPIC_API_KEY` by the SDK and never written to disk or logs. Results contain
prompts, model rationales and usage, with no personal data. Raw run directories stay out of git
(`runs/` is ignored); the analysis summaries and the run manifest (`run.json`: config hash, git commit, SDK
version, scenario hashes) are committed with the report.



## 11. Extending to other providers

Copy this directory to `e2-<provider>/`, change `experiment_id`, `provider`, `models` and prices, and
keep everything else. `run.mjs --provider openai-compatible` uses `src/lib/llm.js` (OpenRouter or any
OpenAI-compatible server, including local vLLM, llama.cpp or Ollama endpoints). Differences that make
cross-provider comparisons weaker, to report with any comparison:

* JSON is requested in the prompt instead of enforced by structured outputs, so schema failures will be
  more common. They are counted as execution failures, not choices.
* Sampling settings must be fixed explicitly (provider defaults differ); record them in the config.
* Reasoning/effort controls are not equivalent across providers. Report each model's setting.
* Open-weights runs should record the exact weights (repository, revision hash) and quantization.
